Journey of a payment

Seven stages from HTTP to settled outcome. Every stage is durable or honestly pending — nothing fails silently.

1

HTTP admission

POST /api/v1/instructions validates, hashes the body, honors Idempotency-Key → 202 new · 200 replay · 409 conflict · 400 invalid.

→
2

Outbox + Postgres

Instruction + outbox event commit in one transaction. Crash between commit and publish recovers by re-reading the outbox.

→
3

IBM MQ transport

Publisher sends to QUEUEDESK.INSTRUCTION.IN (at-least-once). Poison and broken routes park in backout/quarantine, consumer stays alive.

→
4

Worker consumes

Dedups by event id, rebuilds features (amount, velocity, recipient history), then calls the risk gate before any settlement.

→
5

Risk gate

Deterministic rules + optional AI provider answer Q01/Q02. Verdicts: ALLOW · REVIEW · REJECT · NOT_ASSESSED. Holds are visible, never silent.

→
6

Simulated clearing

Mock receiver completes, rejects, or answers uncertain. Lost replies reconcile; unknown receivers stay honestly pending with open tasks.

→
7

Outcome saved

Terminal state + full audit trail in Postgres. Dashboard polls read-only APIs: overview, payments, risk, queues, telemetry.

Idempotent — same key, same result, original IDs preserved Durable — outbox + assessment rows survive restarts Fail-safe — provider faults hold, never allow

Risk gate in detail

Rules are deterministic local facts; the AI provider is context only. No score or confidence ever allows, rejects, or names fraud.

Rules → reason codes

  • NEW_RECIPIENT — sender has never paid this receiver → REVIEW
  • UNUSUAL_AMOUNT — amount far from sender baseline → REVIEW
  • SIMULATED_POLICY_BLOCK — ≥ $95,000 to a new recipient → REJECT
  • Faults re-evaluate rules first; quiet traffic holds NOT_ASSESSED with the fault's own status

Modes + live meter

  • OFF — gate short-circuits · RULES_ONLY — no provider call
  • RULES_PLUS_MOCK — deterministic seeded provider, free forever
  • RULES_PLUS_JEV — live TypeSafe Jev jev-1.13.0, key file 600 + gitignored
  • Every Jev success persists token usage; the durable SUM ledger refuses new calls past the $1 budget — restarts never reset the cap

Assessment outputs

  • ALLOW — no rule matched, provider OK → proceeds to clearing
  • REVIEW — rule matched → RISK_HELD with reason codes
  • REJECT — simulated policy block only, with reason
  • NOT_ASSESSED — provider fault/abstention on quiet traffic → held safely

Failure lab (proved, not promised)

  • SC06 MQ outage — 202s queue up, drain after restart with stable IDs
  • SC07/SC08 redelivery + crash — same event twice, one result
  • SC09 lost replies reconcile; unknowns stay pending, never faked
  • SC10 poison held with reason; SC11 rejections carry reasons; SC12 deadline admits honestly-unsent

Operate it

Four commands cover the daily loop.

Start everything

./start-lab

Postgres + MQ containers, API :8080, dashboard :4200. Idempotent; refuses occupied ports.

Send traffic

./scripts/generate --run-id w1 --count 50 --scenario risk-2 --send --observe

Dry-run by default; --send posts, --observe polls to terminal states.

Clean slate

./scripts/reset-lab

Truncates run data, drains queues. Deliberate reset also zeroes the Jev ledger.

Prove health

./scripts/verify

Three gates: unit suites, SC01–SC12 failure lab, k8s-verify. Exit 0 or it says why.
